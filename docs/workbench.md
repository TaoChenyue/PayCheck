# 账单工作台操作说明

本地 Web 工具：BOC / 支付宝 / 微信三源账单的 HTML 展示 + SQLite 导入（Python 标准库 HTTP 服务，无 Web 框架）。

## 启动

```bash
# 启动并自动打开浏览器（默认库文件 paycheck.db，相对启动目录；端口 8765，仅绑定本机）
uv run paycheck --open

# 自定义库文件与端口
uv run paycheck --db ./my.db --port 8765

# 自定义 BOC PDF 转换目录（默认 <库文件目录>/boc_csv）
uv run paycheck --convert-dir ./boc_csv

# 或通过模块运行
uv run python -m paycheck_workbench
```

| 启动参数 | 默认值 | 说明 |
|----------|--------|------|
| `--db` | `paycheck.db`（相对启动目录） | SQLite 库文件路径；日志文件 paycheck.log 与之同目录 |
| `--convert-dir` | `<库文件目录>/boc_csv` | BOC PDF 转换产出的 CSV 存放目录 |
| `--host` | `127.0.0.1` | 监听地址，仅本机使用 |
| `--port` | `8765` | 监听端口 |
| `--open` | 关 | 启动后自动打开浏览器 |
| `--version` | — | 打印版本号 |

> pip 安装后可直接运行 `paycheck`（不带 `uv run` 前缀）；旧入口 `paycheck-workbench` 保留为别名，仍可使用。启动日志与运行日志见 [logging.md](logging.md)。

## 页面结构

- **总账户**：左侧导航栏的一级主视图、默认首页（打开应用即进入）。三源合并视图，收支属性与标签管理只在这里做。
- **数据源**：二级分组视图，含 BOC / 支付宝 / 微信三个子视图（各带笔数徽标），原始账单只读，职责是导入与查看；任一点导航项直达。
- 主区顶部有视图标题行说明当前视图职责；「数据源」分组下方为筛选区块。

## 导入账单

### 单文件导入（预览 → 确认）

1. 进入某个数据源视图（如 BOC），点「导入账单」；总账户空态（三源皆空）时会引导「去数据源导入」。
2. 选择文件后先看**解析预览**：列样例、日期范围、收/支分布。
3. 预览同时给出**去重比对**：新增多少、重复跳过多少。
4. 确认后写入 SQLite；同一文件重复导入时全部命中去重，幂等不产生重复行。

### 批量导入（多文件）

1. 导入入口支持一次选择多个文件（多选/拖拽，按当前视图限定类型：BOC CSV / 支付宝 GBK CSV / 微信 XLSX，兼容 CSV 变体）。
2. 逐文件统计 + 合并去重比对，确认后逐文件写入并显示进度与结果。
3. 类型不符的文件明确提示且不写入。

## BOC PDF 转换（顶栏「转换 PDF」）

1. **选文件**：选一个或多个 PDF，或直接选文件夹；BOC 空态页也有次按钮入口。
2. **（可选）调高级选项**：渲染精度（低/标准/高）、超时、覆盖同名 CSV，详见 [pdf-options.md](pdf-options.md)。
3. **转换**：后台执行，可收起弹窗继续干别的，进度轮询；支持中途停止（已完成文件 CSV 保留、进行中文件丢弃）。

> 转换仅支持 GPU：打开弹窗时自动探测，未检测到 GPU 时弹窗会提示转换不可用并禁用开始按钮。
4. **结果视图**：逐文件显示成功/跳过/失败与交易数；转换出的 CSV 与 PDF 同名存入转换目录，不导入也可直接取用。
5. **一键导入**：结果可直接导入 BOC 数据源，复用导入预览与去重比对。

## 明细表格与汇总卡片

- 明细表格支持：排序、分页、行展开详情、列显隐。
- 汇总卡片随筛选联动（收入/支出/不计收支/期末余额或笔数）。

## 筛选与搜索

- **筛选区块**（左侧导航栏「数据源」分组下方，标题行可折叠；折叠且存在激活筛选时显示激活筛选数徽标）：日期快捷档位、收/支多选、分类多选（总账户视图为来源多选）、属性与标签（仅总账户）、金额区间、重置筛选；筛选状态按视图记忆。
- **关键词搜索**：主区工具栏搜索框，300ms 防抖。

## 收支属性（仅总账户视图）

- **方向约束铁律**：方向=收入的行只能是收入或不计，方向=支出的行只能是支出或不计，永不反向。
- 不计收支/中性行默认不计、可改为计入（计入方向按金额符号定：正=收入、负=支出）。
- 有效属性 = 覆盖 > 原始方向；「不计」行整行置灰，属性列点击即切换计入 ↔ 不计。
- 属性标记写入旁表（`total_overrides`），不改动数据源原始账单；数据源视图始终展示原始收/支。

## 批量操作

1. 勾选 ≥1 行即出现批量操作栏：设为计入 / 设为不计 / 打标签… / 清除选择。
2. 筛选结果多于当前页时提供「选择全部筛选结果」全量模式，操作作用于整个筛选结果。

## 标签组

- **创建**：标签管理弹窗自建标签（名称唯一、自动 8 色循环）。
- **管理**：支持改名、删除（删除仅解除关联，不影响账单）。
- **使用**：行标签多对多、重复打幂等；标签列 chips 带组颜色（chip × 可移除单行标签）；筛选区块「标签」多选筛选（命中任一勾选标签即显示，无标签行仅全部未勾选时显示）。

## 数据与旁表说明

- 三张源表 `boc_transactions` / `alipay_transactions` / `wechat_transactions`：源明细列全量入库 + `source_file` / `imported_at` / `dedup_key`（UNIQUE）；解析时自动跳过文件信息头定位表头。
- 旁表存储（三源明细表不加列）：
  - `total_overrides`：source + row_id 联合主键、counted、updated_at，稀疏，只存用户动过的行；覆盖挂在行 id 上，重复导入不丢。
  - `tag_groups`：名称唯一 + 8 色循环。
  - `row_tags`：行 ↔ 标签组多对多。
- 覆盖 / 标签 / 属性互相独立，导入流程零改动。
- 总账户 API：`PUT /api/total/overrides`（批量设属性，ids / filter 两种 scope）、`GET/POST /api/tags`、`PUT/DELETE /api/tags/{id}`、`PUT /api/tags/apply`（批量打/移除标签）；`/api/rows`、`/api/summary` 的 total 分支为标准 page 分页与计入口径结构。
